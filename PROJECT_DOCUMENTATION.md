## PART 1: SYSTEM OVERVIEW AND TECHNOLOGIES

### 1. Introduction

#### 1.1 General Overview

This Final Year Project is a **comprehensive nutrition tracking and recommendation platform** that combines artificial intelligence, multiple data sources, and cross-platform accessibility to help users make informed dietary decisions. The system integrates:

- **Multi-platform interfaces** (Web UI and Mobile App)
- **AI-powered features** (meal image analysis, personalized recommendations, chatbot)
- **Multiple nutritional databases** (USDA FoodData Central, scraped recipe data, YouTube content)
- **Natural Language Processing** for food input parsing
- **Real-time nutritional analysis** with visual feedback

The project addresses the growing need for accessible, intelligent nutrition guidance by leveraging modern web technologies, machine learning APIs, and comprehensive food databases.

#### 1.2 Problem Statement

Modern consumers face several challenges in managing their nutrition:

1. **Information Overload**: Difficulty finding reliable, personalized nutritional information
2. **Manual Data Entry**: Time-consuming process of logging meals and tracking nutrients
3. **Lack of Personalization**: Generic dietary advice that doesn't consider individual health conditions
4. **Scattered Resources**: Recipes, nutritional data, and health advice exist in separate platforms
5. **Accessibility Barriers**: Many nutrition tools require technical knowledge or are not mobile-friendly

#### 1.3 Project Aim

To develop an **intelligent, multi-platform nutrition tracking system** that:
- Simplifies meal logging through AI-powered image recognition and natural language input
- Provides evidence-based, personalized health recommendations
- Integrates multiple nutritional data sources into a unified interface
- Delivers an accessible experience across web and mobile platforms
- Empowers users to make informed dietary decisions through comprehensive visualizations

#### 1.4 Specific Objectives

1. **Data Integration**
   - Integrate USDA FoodData Central database (300,000+ foods)
   - Scrape and maintain recipe database from nutrition-focused websites
   - Build YouTube video database for educational content

2. **AI-Powered Features**
   - Implement meal image analysis using Google Gemini Vision API
   - Develop NLP-based food input parser
   - Create intelligent nutrition chatbot with specialized prompts

3. **User Experience**
   - Build responsive web interface with intuitive navigation
   - Develop cross-platform mobile application using React Native/Expo
   - Design comprehensive nutrient visualization with tooltips

4. **Backend Infrastructure**
   - Develop REST API server with Flask
   - Implement local SQLite databases for fast querying
   - Create efficient data scraping and update mechanisms

5. **Health Features**
   - Generate evidence-based health advice with academic references
   - Provide personalized meal recommendations
   - Display comprehensive nutritional breakdowns with DRI comparisons

#### 1.5 Scope and Limitations

**Scope:**
- Nutritional tracking for foods in USDA database and scraped recipes
- AI-powered meal analysis and recommendations
- Web and mobile interfaces for iOS/Android
- Educational content integration (YouTube videos, recipes)
- Evidence-based health advice generation

**Limitations:**
- Relies on third-party APIs (Gemini AI, YouTube Data API, USDA API)
- Image recognition accuracy dependent on photo quality
- Recipe database limited to selected nutrition-focused channels
- No real-time synchronization between devices (local storage)
- Academic references generated by AI (require manual verification for critical use)

**Data Flow:**
1. User interacts with Web UI or Mobile App
2. Interface sends API request to Flask server
3. Server processes request (searches databases, calls AI APIs, etc.)
4. Results returned to interface
5. UI displays formatted information to user

#### 5.2 System Architecture

**Architecture Pattern**: **Client-Server with Microservices Approach**

**Components:**

**1. Frontend Layer**
   - **Web UI**: Vanilla JavaScript SPA (Single Page Application)
   - **Mobile App**: React Native with Expo framework
   - **Shared Features**: API client, state management, UI components

**2. Backend Layer**
   - **Main Flask Server** (port 5001): Primary API gateway
   - **YouTube API Service** (port 5002): Dedicated YouTube data service
   - **Python Modules**: Reusable scrapers and utilities

**3. Data Layer**
   - **SQLite Databases**: Local storage for USDA foods and YouTube videos
   - **JSON/CSV Files**: Static recipe database
   - **Environment Variables**: API keys and configuration

**4. External Services**
   - **Google Gemini AI**: Chat, health advice, image analysis
   - **USDA FoodData Central API**: Fallback for food data
   - **YouTube Data API v3**: Video metadata retrieval

#### 5.4 Detailed Design Diagrams

**Database Schema - USDA Foods:**

```sql
-- Foods table
CREATE TABLE foods (
    fdc_id INTEGER PRIMARY KEY,
    data_type TEXT NOT NULL,  -- 'Foundation', 'SR Legacy', etc.
    description TEXT NOT NULL,
    publication_date TEXT
);

-- Full-text search virtual table
CREATE VIRTUAL TABLE foods_fts USING fts5(
    description,
    content=foods
);

-- Nutrients table
CREATE TABLE nutrients (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    unit_name TEXT NOT NULL  -- 'g', 'mg', 'mcg', etc.
);

-- Food-Nutrient junction table
CREATE TABLE food_nutrient (
    fdc_id INTEGER,
    nutrient_id INTEGER,
    amount REAL,
    FOREIGN KEY (fdc_id) REFERENCES foods(fdc_id),
    FOREIGN KEY (nutrient_id) REFERENCES nutrients(id),
    PRIMARY KEY (fdc_id, nutrient_id)
);
```

**Database Schema - YouTube Videos:**

```sql
CREATE TABLE youtube_videos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id TEXT UNIQUE NOT NULL,
    title TEXT NOT NULL,
    description TEXT,
    channel_id TEXT NOT NULL,
    channel_title TEXT,
    published_at DATETIME,
    thumbnail_url TEXT,
    duration INTEGER,  -- seconds
    keywords TEXT,  -- comma-separated
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    is_active BOOLEAN DEFAULT 1
);

CREATE INDEX idx_video_id ON youtube_videos(video_id);
CREATE INDEX idx_channel_id ON youtube_videos(channel_id);
CREATE INDEX idx_published_at ON youtube_videos(published_at);
```

  - query: string (required) - search term
  - limit: integer (default: 20) - max results
